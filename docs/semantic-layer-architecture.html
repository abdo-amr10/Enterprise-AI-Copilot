Semantic Layer Architecture

Current implementation audit. Backend is the system of record; the AI runtime processes data supplied by Backend.

Implemented

Backend-resolved sources
  → POST /internal/semantic/generate-draft (Backend-assigned layer/revision IDs)
  → in-memory initial draft
  → POST /internal/semantic/validate (draft + schema + relationships)
  → in-memory validated draft/result
  → Backend persistence and lifecycle
  • Generation: FullRebuild and Incremental generation, deterministic merge, and object identity assignment. Backend assigns semantic_layer_id and revision_id before the processing call; the AI carries them forward without replacement. It has no local Semantic Layer file I/O.
  • Validation: validates Backend-provided schema and authoritative relationships; FullRebuild requires represented source relationships, while Incremental validates the complete merged draft. It performs a complete validation again after every auto-fix, returning only the final status. Successful validation returns validated: true, status: "validated", and still requires human review.
  • Review: /internal/semantic/review is in-memory only. API decisions are Approve/Reject; the application normalizes them to approve/reject. Approval requires a passed validation result; rejection requires comments. Backend persists the returned decision, review timestamp, reviewer, and draft.
  • Rejection loop: Backend persists rejection, Admin edits the same revision, and Backend submits it to the same /internal/semantic/validate processing path. The loop may repeat; rejected revisions cannot be indexed.
  • Embedding/index construction: an approved Backend-provided layer can be processed in memory by SemanticDocumentBuilder → EmbeddingService → VectorIndex. The configured offline model is BAAI/bge-m3 at ai/models/embeddings/bge-m3 (1024 dimensions). It loads lazily with local_files_only=True, batches documents, and emits normalized float32 vectors. FAISS IndexFlatIP is the vector-index implementation; its derived artifact metadata includes index version, layer/revision IDs, model/version, dimension, and document count.

Ownership

  • Backend: uploaded files, source IDs, drafts, revisions, validation/review state, approval state, revision lineage, versions, and approved content.
  • AI runtime: generation, validation, auto-fix, in-memory review transformation, document construction, embedding, index construction, and later retrieval processing.

Generation/Validation use ai/src/api/generation_validation_dependencies.py; in-memory review uses ai/src/api/semantic_review_dependencies.py. Both are isolated from local repository, vector-store, schema-file, and sample-data dependencies.

Backend-facing processing contracts

  • POST /internal/semantic/generate-draft: Backend-assigned layer/revision IDs, trigger type, source-file IDs for lineage, resolvedSources, and for Incremental an approved base layer, base revision ID, and affected objects.
  • POST /internal/semantic/validate: draft, authoritative schema, and authoritative relationships.
  • POST /internal/semantic/review: a draft, validation result, title-case review decision, reviewer ID, and rejection comments when rejecting.

Development/reference tooling retained

docs/database_metadata/, ai/outputs/semantic_layer/, and the scripts build_semantic_layer.py, validate_and_review.py, build_semantic_index.py, and run_semantic_layer_pipeline.py remain historical/local tooling. Their local JSON and NumPy index artifacts are not authoritative production state.

Planned / next migration

Retrieval and Text-to-SQL still use local FileSemanticRepository, LocalVectorStore, DatabaseSchemaProvider, and ReferenceDataPreflight. They must be migrated to receive Backend-approved revision/schema/reference inputs or Backend-controlled derived-index storage. No such Backend endpoint or storage contract exists in this repository today.

The next phase is the Retrieval/Text-to-SQL migration. The BGE-M3 artifact is present and selected, but SentenceTransformers/FAISS must be installed in the deployment runtime before the real model/index integration checks can execute there.
